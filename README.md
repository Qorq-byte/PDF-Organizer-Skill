# 📚 PDF Organizer Skill

> 一个面向 AI Agent 的智能 PDF 整理、分类、摘要与知识索引 Skill。

把散落在电脑里的 PDF，从：

> “我不知道这个文件是什么，也懒得一个个打开”

变成：

> **“知道它是什么、讲了什么、重点在哪里、应该放到哪里。”**

---

## ✨ 项目简介

`PDF Organizer` 是一个通用型 AI Agent Skill，专门用于处理和整理大量 PDF 文档。

它不只是简单的 PDF 总结器，而是尝试完成完整的：

```text
PDF
 ↓
文档识别
 ↓
内容提取
 ↓
智能分类
 ↓
关键词提取
 ↓
摘要生成
 ↓
重点信息提取
 ↓
目录/章节识别
 ↓
重复与版本检测
 ↓
文件归档建议
 ↓
知识索引
```

适合处理：

* 学习资料
* 课程讲义
* 教材
* 学术论文
* 科研资料
* 项目文档
* 工作报告
* 会议材料
* 产品说明书
* 通知公告
* 合同和协议
* 电子书
* 资料汇编
* 扫描 PDF

---

# 🚀 核心功能

## 1. 🔍 自动识别 PDF 类型

Agent 会根据文件名、标题、目录、正文结构和语义内容判断 PDF 类型。

例如：

```text
论文
教材
课程讲义
实验报告
项目报告
会议资料
技术文档
产品说明书
合同
通知
电子书
其他
```

同时给出分类置信度：

```text
类型：学术论文
置信度：93%

原因：
文档包含摘要、关键词、方法、实验结果和参考文献。
```

当信息不足时不会强行判断：

```text
document_type: unknown
confidence: low
```

---

# 2. 🗂️ 自动分类归档

Skill 支持多级分类，而不是只有简单的文件夹标签。

例如：

```text
学习资料/
├── 英语/
│   ├── CET-4/
│   └── CET-6/
│
├── 数学/
└── 计算机/
    ├── 数据结构/
    ├── 操作系统/
    └── 人工智能/
```

科研资料：

```text
科研/
├── AI/
│   ├── LLM/
│   ├── RAG/
│   └── Agent/
│
└── Computer Vision/
```

分类树会根据实际文档内容动态生成。

---

# 3. 📝 PDF 自动摘要

提供三种摘要级别。

### Quick

适合快速浏览：

```text
一句话摘要
+
3 个核心重点
+
5 个关键词
```

### Standard

默认模式：

```text
文档类型
一句话摘要
核心内容
关键词
核心结论
重要章节
```

### Detailed

适合研究：

```text
文档结构
章节摘要
重点信息
关键数据
核心结论
重要页码
关键词
```

---

# 4. 🧠 一句话理解整份 PDF

例如：

```text
文件：
transformer-paper.pdf
```

输出：

```text
一句话摘要：

本文介绍 Transformer 架构及其基于 Attention
机制处理序列信息的方法，并验证其在机器翻译任务中的效果。
```

让用户无需打开几十页文档就能快速知道：

> **“这份 PDF 到底讲什么？”**

---

# 5. 🔑 自动提取关键词

自动识别文档中的：

* 核心主题
* 技术术语
* 专业概念
* 人物
* 机构
* 产品
* 方法
* 重要概念

例如：

```text
#Transformer
#Attention
#LLM
#RAG
#MachineLearning
```

默认只保留主要关键词，避免产生几十个没有意义的标签。

---

# 6. 💡 核心结论提取

自动回答：

> **“这份 PDF 最值得记住的内容是什么？”**

例如：

```text
核心结论：

1. Transformer 使用 Attention 机制处理序列信息。
2. Self-Attention 可以建立不同位置之间的关联。
3. 实验结果表明该架构在特定任务上具有明显优势。
```

不同类型文档会使用不同的提取策略。

### 学术论文

重点提取：

```text
研究问题
研究方法
主要发现
创新点
局限性
```

### 报告

重点提取：

```text
主要发现
关键数据
趋势
问题
建议
```

### 通知

重点提取：

```text
对象
时间
地点
要求
截止日期
```

### 产品说明书

重点提取：

```text
功能
使用步骤
注意事项
限制
```

---

# 7. 📑 自动识别目录与章节

如果 PDF 本身存在目录：

```text
1. Introduction
2. Method
3. Results
4. Discussion
5. Conclusion
```

直接提取原始目录。

如果没有目录，但能够从正文中可靠识别章节，则生成：

```text
自动目录
```

并明确标记：

```text
toc_source: inferred
```

不会把推断内容伪装成原始目录。

---

# 8. 📍 重要页码定位

自动识别：

```text
摘要
核心结论
关键数据
重要图表
重点章节
用户指定内容
```

例如：

```text
重要页码：

P.1  摘要
P.5  方法
P.9  核心实验结果
P.15 结论
```

用户可以快速跳转到关键页面。

---

# 9. 📊 关键数据提取

自动识别 PDF 中的重要：

```text
数字
日期
金额
比例
统计数据
实验结果
指标
```

例如：

```text
2026 年预算：120 万元
准确率：94.2%
用户增长：38%
```

尽量保留：

```text
文件
页码
上下文
```

方便用户回查原文。

---

# 10. 🔗 多个 PDF 的关系分析

当一次上传多个 PDF 时，Skill 会分析它们之间是否存在：

```text
同主题
同作者
同课程
同项目
同版本
补充材料
前后版本
相关资料
```

例如：

```text
项目报告
├── Draft
├── v1
├── v2
└── Final
```

或者：

```text
Paper A
   ↓
Paper B 为更新版本

Paper C
   ↓
Paper A 的补充实验
```

---

# 11. ♻️ 重复 PDF 检测

批量整理时自动发现：

### 完全重复

```text
A.pdf
B.pdf

→ 内容基本一致
```

### 高度相似

```text
A.pdf
B-final.pdf

→ 正文大部分一致
→ 存在少量修改
```

### 主题相关

```text
A.pdf
B.pdf

→ 都讨论 RAG
→ 但不是重复文件
```

避免把“相关”误判成“重复”。

---

# 12. 🕐 版本识别

自动识别：

```text
Draft
v1
v2
v3
Revision
Final
Final-final
```

结合：

* 文件名
* 日期
* 版本号
* 修改记录
* 内容差异

形成版本关系：

```text
报告
├── Draft
├── v1
├── v2
└── Final
```

无法确认最新版本时，会明确提示：

```text
latest_version: uncertain
```
